# Публикация в Vercel

## Репозиторий

Новый репозиторий должен быть **Private**. Не загружать соседние папки рабочего пространства, локальную историю чата, `.env`, `node_modules`, `.openai` или `.vercel`.

Основная ветка: `main`. Ветка подготовки: `deploy/vercel-ready`. После подключения Vercel каждое обновление ветки может создавать preview; production публикуется из выбранной Production Branch. Не отключать проверку доступа к закрытому репозиторию.

## Первый запуск

1. Открыть [создание проекта Vercel](https://vercel.com/new), подключить GitHub и разрешить доступ только к нужному закрытому репозиторию.
2. Выбрать подходящую команду и тариф. Hobby не рассчитан на коммерческое использование сайта платных услуг.
3. Root Directory оставить корнем репозитория, Framework Preset выбрать Other, Node.js 24.x. Настройки сборки читаются из `vercel.json`: установка `npm ci --include=dev`, сборка `npm run build`, результат `build`.
4. Включить доступ к системным переменным окружения Vercel. При известном домене добавить `SITE_URL=https://ваш-домен` только в Production. Не задавать фиктивный адрес. Без `SITE_URL` используется `VERCEL_PROJECT_PRODUCTION_URL`, затем `VERCEL_URL`.
5. Production Branch установить `main`. Ветки изменений проверять через preview.
6. Подключить домен в Settings > Domains, применить DNS-записи, предложенные Vercel, дождаться HTTPS. После смены `SITE_URL` выполнить Redeploy.

## Приёмка перед публичным запуском

- Проверить меню, закрытие по Escape, клавиатурную навигацию и повторный выбор текущего пункта.
- Проверить «Мою историю», все три пункта подхода и переключение изображений.
- Проверить фильтры услуг, раскрытие описаний и просмотр 13 отзывов.
- Проверить контакты: карточки друг под другом, телефон и мессенджеры, отсутствие внутренней прокрутки и отображение карты.
- Проверить 320/390px, 768/1093px, 1366/1920px и низкие экраны, увеличенный текст и уменьшение анимации в системе.
- В Network/Console проверить отсутствие 404, JavaScript-ошибок и блокировок CSP. Внешняя карта требует сети; её загрузка отдельно зависит от Яндекса.
- Проверить canonical, `og:url`, `og:image`, JSON-LD и `/sitemap.xml`: все адреса должны вести на текущий production-домен.
- Preview должен содержать `noindex`, а `/robots.txt` - `Disallow: /`.
- Проверить разрешения на публикацию фото и отзывов, в том числе имён, номеров телефонов и сведений о здоровье на скриншотах. При необходимости обезличить оригиналы до публикации.
- Проверить актуальность услуг, цен, квалификаций, адреса и расписания у владельца сайта.

## Дальнейшие изменения

Редактировать файлы в `dist/`. Перед push запускать `npm run build`. Сохранять `package-lock.json` при изменении зависимостей. Автоматические проверки GitHub не являются защитой production сами по себе: включить требование успешного CI перед слиянием в `main` в настройках репозитория, если тариф и правила аккаунта это поддерживают.

Не использовать `git push --force` для обычных обновлений. Для отката выбрать предыдущую успешную production-публикацию в Vercel и затем отменить проблемный коммит через `git revert`, чтобы история Git соответствовала опубликованной версии.
