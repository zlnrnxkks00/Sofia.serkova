# София Серкова

React + Vite + SCSS с предварительной генерацией HTML. На хостинг публикуются обычные статические файлы: сервер Node.js и база данных посетителям не требуются. Ветка переноса: `migration/react-vite-scss`.

## Структура

- `src/sections/` - React-компоненты всех секций.
- `src/hooks/` - управление мобильным меню, фокусом и блокировкой прокрутки.
- `src/motion/` - анимации canvas, счётчиков и закреплённой сцены с очисткой ресурсов при размонтировании.
- `src/data/` - тексты истории, услуги и манифест отзывов.
- `src/styles/` - SCSS; порядок правил и адаптивные размеры сохранены.
- `dist/` - неизменённая прежняя версия и оригинальные ресурсы. Не редактировать в ветке переноса.
- `scripts/` - проверка ресурсов и подготовка публикации.
- `tests/` - проверки прежней версии; `tests/react/` - проверки переноса, гидратации и готового HTML.
- `build/` - готовый сайт, создаваемый сборкой; не редактировать и не добавлять в Git.
- `vercel.json` - настройки Vercel и защитные HTTP-заголовки.
- `.github/workflows/check.yml` - автоматическая проверка каждого push и pull request.
- `docs/BEGET.md` - публикация React-сборки на Beget.
- `docs/MIGRATION.md` - границы переноса, проверки и ограничения.
- `.ssr/` и `.vite-public/` - временные результаты сборки, не добавляются в Git и не публикуются.

## Проверка

Нужен Node.js 24 LTS, не ниже 24.15. Используется npm и зафиксированный `package-lock.json`.

```sh
npm ci --include=dev
npm run dev
```

Полная проверка и сборка:

```sh
npm run build
```

`npm run build` проверяет прежнюю версию, запускает 17 базовых наборов тестов, собирает клиент Vite, генерирует HTML из React и запускает 5 наборов проверок переноса. Все тексты, цены, контакты и 13 отзывов присутствуют в готовом HTML до запуска JavaScript. Затем `hydrateRoot` подключает интерактивность к существующей разметке.

Сборка не меняет `dist/`. CSS и JavaScript получают хеши в именах. В `build/` копируются используемые ресурсы и лицензии, формируются метаданные, `robots.txt` и sitemap. Старый скрипт и старая библиотека иконок в React-публикацию не входят. Для проверки только React-сборки: `npm run build:react`, затем `npm run test:react`. `npm test` также выполняет сборку; `npm run check` отдельно проверяет сохранённые исходники прежней версии.

Локальная сборка без адреса сайта закрыта от индексации. Для production вне Vercel:

```sh
SITE_URL=https://your-domain.example npm run build
```

`SITE_URL` - публичный HTTPS-адрес без пути. Это не секрет. Скрипт получает его из окружения; файл `.env.example` является примером, `.env` автоматически не загружается.

## Публикация

Для Beget Blog собрать с реальным `SITE_URL` и загрузить **содержимое `build/`** в папку сайта `public_html`. Не загружать `src`, `dist`, `.ssr`, `.vite-public`, `.git` или `node_modules`. HTTPS и редирект включаются в панели Beget; `vercel.json` на Beget не применяется. Подробности в `docs/BEGET.md`.

Настройки Vercel сохранены как дополнительный вариант: корень репозитория, Framework Preset Other, Node.js 24.x, Output Directory `build`. На Vercel без `SITE_URL` используется системный production-адрес, а preview закрывается от индексации. Рабочая ветка не заменяется и сайт автоматически на Beget не загружается.

Репозиторий опубликован открыто с разрешения владельца. Старый снимок сохранён в ветке `backup/current-static`. Защита доступа к развёрнутому preview настраивается отдельно на хостинге.

Vercel Hobby предназначен для личных некоммерческих проектов. Для коммерческого сайта услуг нужно выбрать подходящий план, не активируя платные услуги автоматически. См. [правила Vercel](https://vercel.com/docs/plans/hobby).

## Важное

Внешние обращения посетителя: Яндекс Карты и переходы в мессенджеры. Аналитика, cookies-приложения и формы сбора данных не добавлялись. Перед публичным запуском необходимо подтвердить актуальность контактных данных, право публикации фото и разрешение на публикацию отзывов с персональными данными.

Автоматические проверки не заменяют визуальную проверку настоящего развёрнутого сайта на телефоне, планшете и ПК.
